# TaskFlow — Project & Task Tracker

A complete task/project tracking tool: FastAPI backend, SQLite database,
and a Kanban-board frontend (plain HTML/CSS/JS — no build step required).

## What's inside

```
taskflow/
├── backend/
│   ├── main.py          FastAPI app — all API routes
│   ├── models.py        SQLAlchemy tables: users, projects, tasks, comments, attachments
│   ├── schemas.py       Pydantic request/response validation
│   ├── crud.py          Database read/write functions
│   ├── database.py      SQLite connection (creates tasks.db here)
│   ├── seed.py          Optional: fills the board with sample data
│   ├── requirements.txt
│   └── uploads/         Uploaded file attachments are stored here
├── frontend/
│   ├── index.html       Dashboard / Board / Team pages
│   ├── styles.css
│   └── app.js           All frontend logic (calls the API with fetch)
└── README.md
```

## How to run it

1. **Open a terminal in the `backend` folder:**
   ```
   cd taskflow/backend
   ```

2. **Create a virtual environment and install dependencies:**
   ```
   python -m venv .venv
   .venv\Scripts\Activate.ps1        # Windows PowerShell
   # or: source .venv/bin/activate   # Mac/Linux

   pip install -r requirements.txt
   ```

3. **(Optional) Seed sample data** so the board isn't empty on first run:
   ```
   python seed.py
   ```

4. **Start the server:**
   ```
   uvicorn main:app --reload
   ```

5. **Open your browser** to:
   ```
   http://127.0.0.1:8000
   ```
   The FastAPI backend serves the frontend directly — one server, one URL, nothing else to run.

   Interactive API docs (auto-generated by FastAPI) are available at:
   ```
   http://127.0.0.1:8000/docs
   ```

## The database

Everything is stored in **one file**: `backend/tasks.db` (created automatically
the first time you run the server). You can open this file directly in
[DB Browser for SQLite](https://sqlitebrowser.org/) at any time — while the
server is running or stopped — to inspect or manually edit rows. Any changes
you make through the web UI are written to this same file immediately.

### Tables
| Table | Purpose |
|---|---|
| `users` | Team members who can be assigned to tasks |
| `projects` | Top-level projects/workspaces |
| `tasks` | Individual tasks: title, description, status, priority, progress %, dates |
| `task_assignees` | Many-to-many link between tasks and users |
| `comments` | Comment thread per task |
| `attachments` | Uploaded file metadata per task (actual files live in `backend/uploads/`) |

## How data flows

1. The browser (`app.js`) calls the FastAPI backend at `/api/...` using `fetch()`.
2. FastAPI validates the request with a Pydantic schema (`schemas.py`).
3. `crud.py` reads or writes rows in `tasks.db` through SQLAlchemy.
4. FastAPI returns JSON, which `app.js` uses to re-render the page — no reload needed.
5. Every create/update/delete refreshes the dashboard stats and board immediately,
   so Dashboard, Board and Task Detail always show the same live data.

## Core features implemented

- **Projects:** create, rename/edit, delete (with confirmation)
- **Tasks:** create, edit, delete (with confirmation), drag-free status change via the edit form,
  priority (Low/Medium/High/Urgent), progress % slider, start/due dates, multiple assignees
- **Board view:** four columns — To Do / In Progress / In Review / Completed — matching the
  reference design, with color-coded priority badges and avatar stacks
- **Filtering:** by assignee, by priority, and free-text search across title/description
- **Task detail panel:** full description, progress bar, comments thread, file attachments
  (upload + download + remove)
- **Team page:** add/remove people who can be assigned to tasks
- **Dashboard:** total / to-do / in-progress / in-review / completed counts, plus a project
  overview grid with per-project completion percentage

## Notes

- No authentication/login system — this is an internal single-workspace tool, kept deliberately simple.
- No AI features, chatbots, or third-party integrations, per the "keep it simple" requirement.
- File attachments are saved to `backend/uploads/` with a randomized filename on disk (to avoid
  collisions) while the original filename is preserved in the database for display/download.
